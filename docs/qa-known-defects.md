# QA 已知缺陷

本文件只記錄目前可重現的產品風險。本次測試導入不改變產品政策；修復後應把對應案例轉成阻擋回歸的自動化測試。

## QA-001：資料 API 缺少身分與權限檢查

- 嚴重度：高
- 狀態：待處理
- 重現：未帶任何身分資訊呼叫 `GET` 或 `PUT /api/project-data`。
- 實際：Route Handler 直接讀寫資料。
- 預期：依產品存取政策驗證身分與讀寫權限。
- Regression test：匿名請求應被拒絕，已授權使用者才可讀寫自己的資料。

## QA-002：所有使用者共用固定儲存鍵

- 嚴重度：高
- 狀態：待處理
- 重現：兩個不同使用者依序儲存專案。
- 實際：兩者都 upsert `project_store.id = "default"`，後寫入者覆蓋前者。
- 預期：確認產品是單一共享計畫或依 workspace／user／project 隔離；資料鍵必須反映該政策。
- Regression test：不同資料擁有者不得互相覆蓋，或共享模式需有明確衝突處理。

## QA-003：API 接受任意 payload

- 嚴重度：高
- 狀態：待處理
- 重現：向 `PUT /api/project-data` 傳送空物件、錯誤型別或超大／不完整結構。
- 實際：任何可解析 JSON 都會被序列化儲存。
- 預期：伺服器驗證 `StoredProjectData` schema、資料大小及必要欄位，錯誤回傳 4xx。
- Regression test：列舉缺欄位、錯誤型別、未知狀態與超限 payload。

## QA-004：不存在的日期會被自動滾動

- 嚴重度：中
- 狀態：待處理
- 重現：匯入 `2026-02-31`。
- 實際：JavaScript `Date` 可能把它正規化成三月日期，而不是回報格式錯誤。
- 預期：年月日必須與解析後日期完全一致，不存在的日期應拒絕匯入。
- Regression test：覆蓋非閏年 2/29、2/30、2/31、4/31、月份 0/13。

## QA-005：反向日期的日曆 duration 仍為 1

- 嚴重度：中
- 狀態：待處理
- 重現：設定開始日 `2026-06-20`、結束日 `2026-06-19`。
- 實際：`getDuration` 以最小值 1 正規化；工作天函式則回傳 0，兩者不一致。
- 預期：阻擋反向日期，或所有計算一致回傳 0 並顯示驗證錯誤。
- Regression test：Task、Epic、匯入與彙總應採相同政策。

## QA-006：重複 Epic WBS 的 Task 歸屬不明

- 嚴重度：中
- 狀態：待處理
- 重現：匯入兩筆相同 WBS 的 EPIC，再匯入該 WBS 下的 TASK。
- 實際：畫面可能保留兩個 EPIC，但內部 map 只指向最後一筆，TASK 會掛到最後一筆。
- 預期：拒絕重複 WBS，或定義並提示明確合併政策。
- Regression test：重複 WBS 必須產生可理解的匯入錯誤。

## QA-007：舊測試驗證已不存在的 starter skeleton

- 嚴重度：中
- 狀態：已於自動化測試導入時處理
- 實際：舊測試與目前專案頁面、依賴和 metadata 不一致。
- 處理：以 domain、D1 API 與 Playwright 核心流程測試取代。
