# 操作測試與啟動逾時排查

## 2026-10-02 修正紀錄

GitHub 檢查在 Playwright 啟動網站時等待 120 秒後逾時，尚未執行操作案例。

本機重現確認 `vinext dev` 預設以 `localhost` 啟動，實際監聽 IPv6 `::1:3000`；Playwright 則固定探測 IPv4 `127.0.0.1:3000`。同一個網站的 IPv6 請求回應 200，IPv4 連線被拒絕。

修正將網站啟動命令、就緒探測 URL 與瀏覽器 baseURL 統一到 `127.0.0.1:3000`，並將網站標準輸出加入測試紀錄。不以延長等待時間掩蓋位址不一致。

## 後續發現

啟動恢復後，原有案例暴露出以下問題，於同一修正分支處理：

- 桌面與手機版同時保留狀態文字：測試只查詢目前可見的狀態。
- 任務列表輸入欄缺少名稱：補上與編輯視窗一致的 WBS 任務名稱標籤。
- 新任務名稱是輸入值，且新 Epic 自帶一個 Task：測試驗證新增前後數量及新增欄位值。
- 匯入按鈕與對話框同名：測試明確查詢按鈕。
- 刪除確認按鈕可能自動在中文字間加入空白：在確認視窗內比對可容許空白的按鈕名稱。
- 雲端讀取失敗仍會觸發自動儲存：只有本次頁面成功讀取雲端後才允許寫回。讀取失敗期間繼續保存本機編輯，顯示本機備援；重新載入並成功讀取後才恢復雲端寫入。

離線保護案例保留一份模擬雲端資料，讓 GET 失敗但 PUT 可成功，驗證超過自動儲存等待時間後仍無 PUT、雲端資料未被覆蓋，且重新載入可恢復本機編輯。此修正不加入離線與雲端資料的自動合併功能；重新連線時維持原有的雲端優先載入行為。

## 執行與診斷

```sh
pnpm run typecheck
pnpm run lint
pnpm run test:coverage
pnpm run build
CI=1 pnpm run test:e2e
```

需要查看就緒探測紀錄時：

```sh
CI=1 DEBUG=pw:webserver pnpm run test:e2e --retries=0 --reporter=list
```

操作測試使用模擬資料 API，不直接驗證正式 D1 資料庫或正式環境權限。測試期間避免同時生成 coverage 或其他 HTML 報告，以免開發伺服器偵測檔案變動後重新載入頁面。
